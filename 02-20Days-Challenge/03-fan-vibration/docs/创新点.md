# 创新点：作业没要求、但值得做的四件事

作业只要求三样东西：5 种工况 × 15 组原始录音、时域/频域特征提取代码、盲测视频与抗噪报告。
做到这里已经够分了。这一节写的是**在要求之外多做的四件事**，每条都按同一个格式写：
解决什么问题 → 怎么做 → 结果是什么 → **以及它没能解决什么**。

最后一条最重要。凡是只写「我做了什么、效果很好」的，都是包装；写出「它在哪里失效」的，才是工程。

---

## 创新一　规则 vs 机器学习：为什么最后选了 kNN

### 要回答的质疑

kNN 不是唯一的选择。评委一定会问：**「这么简单的任务，写几条阈值规则不行吗？为什么非要用机器学习？」**

如果答「因为机器学习更先进」，那是外行话。正确的回答只能是：**对比过。**

### 做法

手写一棵阈值树，和 kNN 用同一批 98 段、同一套分组交叉验证：

```
if h2 > 2.10          → 遮挡
elif e_high > 0.260   → 失衡
elif f0 < 35.2        → 一档
elif f0 < 38.9        → 三档
else                  → 五档
```

三个阈值不是拍脑袋，是在全量数据上**扫出来的最优值**（`code/scan_thr.py`，h2 从 1.5 扫到 6.0、e_high 从 0.15 扫到 0.26、f0 两条切线各扫 0.1 Hz 步长）。

> **注意这里有个对自己不利的细节**：规则的最优阈值是在**含测试样本的全量数据**上扫出来的，等于提前看过答案；而 kNN 没有任何可调参数。所以这场对比里，规则是**占了便宜**的一方。

### 结果

| 口径 | 五类 | 三类 |
|---|---|---|
| 手工规则（最优阈值，含作弊） | 57.1 % | 82.7 % |
| kNN（k=3，无参数） | 61.2 % | **90.8 %** |
| **差距** | −4.1 | **−8.1** |

### 差在哪

三类上，规则的错误几乎全是一个方向：**65 段「正常」里有 24 段被误判成「失衡」**。

原因很清楚：`e_high > 0.260` 是一刀切，但正常的 1/3/5 档本来就有 0.147–0.17 的高频，个别段落冲到 0.2 以上；而胶带的中位是 0.211。**两条分布在这个区间是重叠的**，一个阈值切不开，kNN 用的是六个特征的联合分布，才切得开。

### 结论

**选 kNN 不是因为不会写规则，是因为写过、对比过、知道规则差在哪。**
而且规则的优点也是真的 —— 它可解释、不需要存训练数据、在样本极少时更稳 —— 所以正式报告里给的是一条「规则打底、kNN 补充」的建议。

## 创新二　开集检测：没见过的那种故障，它敢不敢说「不认识」

### 要回答的质疑

分类器只有五类。如果明天风扇坏的方式**不在这五类里**（轴承磨损、异物卡死），它会怎么办？

答案是：**它会硬判成某一类，而且很自信。** 这在工业场景里是危险的 —— 一个把「轴承要坏了」报成「五档风有点大」的系统，比不报警更糟。

### 做法

每次留出一整个工况不参与训练，然后问系统：这段信号离你认识的东西有多远？

1. 用其余四类训练；
2. 算每个样本到训练集的 **kNN 距离**（标准化特征空间里最近 3 个点的平均距离）；
3. 门槛取「训练集自身留一距离的 95 分位」；
4. 超过门槛 → 输出「未知故障」，而不是硬判。

### 结果

| 留出的类 | 门槛 | 拒识率 | 误拒率 |
|---|---|---|---|
| C1 一档 | 1.53 | 9 % | 5 % |
| C2 三档 | 1.44 | 5 % | 5 % |
| C3 五档 | 1.55 | 0 % | 5 % |
| C4 胶带 | 1.56 | 0 % | 6 % |
| **C5 遮挡** | 2.38 | **100 %** | 5 % |

（误拒率固定在 5%，因为门槛就是这么定义的。）

**遮挡这一类的 17 段，到已知四类的距离是 12–53，而门槛只有 2.38 —— 超出 5~22 倍。** 系统会明确说「没见过这种」。

### 但胶带为什么拦不住

这是这条创新里**最值得写的部分**：C4（扇叶贴胶带）的拒识率是 **0%**。

因为胶带本质上只是「五档 + 一点高频」，它在特征空间里**紧贴着正常五档**。把它拦在外面反而是错的 —— 它确实属于「已知故障」的范畴。

### 硬判对照

如果去掉开集，强制归到四类之一，被留出的类会被判成什么：

| 留出 | 硬判结果 |
|---|---|
| C1 | C3×12、C2×11 |
| C2 | C3×12、C1×4、C4×3 |
| C3 | C4×9、C2×8、C1×6 |
| C4 | C3×8、C2×5、C1×3 |
| **C5** | **C2×17** |

**一个只做五选一的分类器，遇到从没见过的遮挡故障，17 次全部判成「三档风有点大」。** 这就是开集检测存在的意义。

### 结论

开集检测管「结构性新故障」，有监督分类管「已知故障的细分」。
**两者互补，缺一不可** —— 而且这个结论是测出来的，不是想出来的。

## 创新三　频谱瀑布：把「失衡」画出来

### 要解决的问题

平均频谱只能说明「高频多了一点」，说不清**多在哪、什么时候多**。答辩现场需要一张能让评审三秒看懂「故障长什么样」的图。

### 做法

挑一对**转速几乎完全相同**的样本（C3_01 与 C4_15，f0 都是 35.2 Hz），这样两张图的差别只可能来自胶带，而不是转速。

对每段做 STFT（4096 点窗、1024 跳），把频率轴按对数重采样到 20 Hz–8 kHz，画成时间-频率-能量瀑布。

### 看到什么

- **低频那一团完全一样** —— 因为转速没变，风量没变。
- **1–4 kHz 明显变亮** —— 胶带让扇叶每转一次多一次扰动，高频能量在时间上出现起伏。

### 诚实的部分

高频占比是 **0.093 → 0.211**，是两倍多，但**不是「一眼可见」的差别**。
所以这张图的作用是**讲给人听**，真正判定还是靠分类器。这一点在图上直接写了，不吹。

图：`figs/fig09_频谱瀑布.png`

## 创新四　位置偏移量化 —— **没做成**

### 原计划

同一档位、不同距离（20 / 40 / 60 cm）各录 15 段，量化「距离每变 10 cm，谱心漂多少 Hz」。

**这是全套里最该做的一条**，因为五类只有 61.2% 而三类有 90.8% —— 掉的那 29 个点，主要就是被录音位置吃掉的。如果能把这个影响量化出来，「为什么档位分不开」就从一句解释变成一组数据。

### 现状：做不了

翻遍 `data/` 与 `results/features.csv`，只有 C1–C5 五类共 98 段，**没有任何按距离分组的录音**。

之前提过「录了 3 段远近运动」，实际没有落到文件里。没有数据，这条就只能是计划，不能写成结果。

### 但如果要补，只需要 45 段

- 固定五档，手机放在 20 / 40 / 60 cm 三个距离，每个距离录 15 段、每段 10 秒；
- 全部录完约 25 分钟；
- 分析脚本可以直接改 `code/evaluate.py`，半天出结果。

补完之后能做三件事：①量化距离对谱心的影响（预期比档位差还大）；②做「每次开机录 3 秒基准、用比值抵消位置」的补偿；③把五类准确率往上推。

**这条留作未完成项，写在这里是为了让评审看到：我们知道还差什么，也知道怎么补。**

## 创新五　振动通道：把题目里「加速度计」那一半补上

**问题**：题目原文是「手机麦克风**与加速度计**」「**声振**信号」。前四节全做了，加速度计是零。

**做法**：5 工况 × 3 段，Phyphox 加速度原始包，480 Hz。去重力后取三个量：水平 RMS（hypot(x,y)）、垂直 RMS（z）、z 轴主频。

**结果**：两个特征恰好正交。

| | 水平 RMS | 垂直 RMS |
|---|---|---|
| 一档 / 三档 / 五档 | 0.038 / 0.035 / 0.098 | 0.090 / 0.090 / 0.094 |
| 五档 + 胶带 | 0.116 | **0.565** |
| 五档 + 半遮挡 | 0.042 | **0.323** |

- **水平看转速**：低速两档 0.035 上下、高速两档 0.10 上下，差 3 倍、无重叠。**声学五分类卡在 61.2% 时，错的全是 C1/C2/C3 之间；同一批档位在振动上一眼拉开**——因为声学测的是空气（受录音位置影响），振动测的是机身（传函固定）。
- **垂直看故障**：正常三档均值挤在 0.088–0.094（单段最高 0.116），两故障 0.32 / 0.56。**一刀切 0.20，9 条正常全在下、6 条故障全在上，零重叠。**

**胶带的指纹**：正常五档谱上 229 Hz 最强；贴一片 2 g 胶带后 **229 Hz 在三条样本里全部归零**，能量塌缩到 1×（29 Hz）与 2×（58 Hz），而转速只掉了 7.6%。不平衡不是「某个峰变高」，是**整个谱重排**。

**它没能解决什么**：只有 15 段、一台设备、每类 3 段，留一法 13/15，置信区间很宽；只取了 z 轴主峰，没做峰族与包络谱；一档有两条的手机倾角是 2.9°（其余 13 条 1.2–1.4°），垂直 RMS 被姿态耦合抬到 0.29，说明**手机测振动，姿态就是量程的一部分**。

→ `docs/振动通道.md`、`figs/fig11_振动通道.png`

## 创新六　分层判定：把 61.2% 拆成 90.8 / 100 / 43.1

**问题**：五分类 61.2% 摆出来很难看。但这个数是三件不同的事混在一起算的平均分。

**做法**：把决策拆成三层，各自单独评估（同一套特征、同一套分组交叉验证）。

**结果**：

| 层 | 问题 | 准确率 |
|---|---|---|
| ① | **有没有故障**（正常 vs 失衡+遮挡） | **90.8%**（89/98） |
| ② | **是哪一种故障**（胶带 vs 遮挡） | **100%**（33/33） |
| ③ | 正常里是哪一档（一/三/五档） | **43.1%**（28/65） |
| — | 直接五分类（对照） | 61.2% |

**结论**：五分类之所以只有 61.2%，**完全是被第③层拖下来的**。第①②层合起来 90.8% × 100% —— 对一台「异常诊断仪」来说，它要回答的两个问题都答对了；「这是第几档」是附加功能，做不到就是做不到（三档转速只差 20%，比录音位置差还小）。

**这比把总分刷到 72% 有用**：一个说不清哪儿错的 72%，不如一个说清「关键任务全对、附加功能不合格」的 61%。

**它没能解决什么**：没提高任何一层的绝对准确率，只是**把误差归了位**。

→ `code/hier.py`

## 创新七　一个负结果：加特征能涨 11 个点，嵌套验证后归零

**问题**：61.2% 到底是「特征不够」还是「物理上限」？

**做法**：在现有 10 个特征里做贪心前向选择，目标函数是分组交叉验证的五分类准确率。

**结果**：

| 配置 | 五类 | 三类 |
|---|---|---|
| 基线 6 特征 | 61.2% | 90.8% |
| 贪心选出的 5 特征 | **72.4%** | 90.8% |
| 全部 10 特征 + k=1 | **75.5%** | 89.8% |

看起来涨了 11 到 14 个点。**但这是选择偏差**——特征是在同一套 CV 上挑的。

于是做嵌套验证：每个留出批次内部重新做一次贪心选择，只用训练批次的数据。

| | 结果 |
|---|---|
| 五类 | **61.2%**（和基线一模一样） |
| 三类 | 86.7%（比基线还低 4 点） |

而且每组选出来的特征子集都不一样（`f0+rms+centroid+e_mid+e_low+h2`、`f0+rms+e_high+e_mid+centroid+h2`……），说明**在 98 段这个量级上，特征选择根本不稳定**。

**结论**：61.2% 不是调参不够，是**这套特征族在「档位」这个维度上的天花板**。要往上走只有加数据，不是换算法。

顺带否掉的还有两个：**多窗口投票**（3 s 窗 / 1.5 s 步，文件级留一）五类降到 58.2%、三类降到 82.7%——短窗把 f0 的分辨率打没了；**Fisher-LDA** 五类 56.1%、三类 88.8%，全都不如质心 kNN。

**它没能解决什么**：没提分。但它把「还能不能更好」这个问题从「不知道」变成了「不能，除非加数据」。

→ `code/clf_greedy.py`、`code/clf_nested.py`、`code/winvote.py`、`code/clf_sweep.py`

## 七条创新与面试五个维度的对应

| 创新 | 主要打哪个维度 |
|---|---|
| 一　规则 vs 机器学习 | ② 逻辑思维与系统权衡（做过对比，有取舍） |
| 二　开集检测 | ③ 自主学习力、④ 承认局限的能力 |
| 三　频谱瀑布 | 表达与沟通（答辩分） |
| 四　位置偏移（未完成） | ① 真实性（知道自己缺什么） |
| 五　振动通道 | ① 真实性（题目写了「声振」，补上另一半）、② 双通道权衡 |
| 六　分层判定 | ② 系统拆解（把总分拆成三件不同的事）、④ 诚实（不刷分） |
| 七　加特征失败（负结果） | ② 方法论（嵌套验证）、④ 抗压（自己否掉自己的 +11 点） |

七条里六条做完了、一条缺数据。**七比四更值钱的地方不是数量，是「七」里有一条是失败** ——
把所有尝试都摆出来、包括没成的那个，比只摆成功的那几条可信。
