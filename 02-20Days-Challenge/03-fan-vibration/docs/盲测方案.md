# 盲测方案（拍视频用）

## 1 要证明什么

「模型不是背下了训练集，而是真的能判断没见过的录音。」

所以盲测必须满足三条：**录音是当场新录的**、**模型没见过**、**判定过程在镜头里**。

## 2 拍摄前准备（不入镜）

1. 把 `code/classify.py` 用**全部 98 段**训练好（这一步提前做完，镜头里不出现）
2. 准备 4 段**新录音**，不放进训练集，命名成 `blind_01 … blind_04`
   - 建议：一档 ×1、五档 ×1、五档贴胶带 ×1、五档半遮挡 ×1（各 10 s）
   - **不要告诉观众哪段是哪个**
3. 把新录音单独放在 `data/blind/`，与训练集物理隔开（便于镜头里展示）

## 3 视频分镜（3 分钟内）

| 时间 | 画面 | 台词要点 |
|---|---|---|
| 0:00–0:20 | 风扇、手机、胶带、纸板同框 | 「四种状态，我一会儿现场录，模型没见过。」 |
| 0:20–0:40 | 镜头对着手机屏幕录制 → 每段 10 s | 「第一段录完了，还没告诉任何人它是哪种状态。」 |
| 0:40–1:00 | 切到电脑，运行一行命令 | 「现在让程序判。」 |
| 1:00–1:30 | 屏幕显示判定结果 + 特征值 | 「它说是『半遮挡』，依据是基频跳到 91.6 Hz、二次谐波比 8.8。」 |
| 1:30–2:00 | **回到实物，揭开真值** | 「这段确实是半遮挡，判对了。」（其余三段同样处理） |
| 2:00–2:30 | 打开 `results/clf_report.json` | 「另外 98 段的成绩在这里：分组交叉验证三类 90.8 %、五类 61.2 %。」 |
| 2:30–3:00 | 对着镜头 | 「五类为什么只有 66 %，我在方法说明第 4 节写了原因，不避讳。」 |

## 4 判定命令（镜头里要展示）

```powershell
cd D:\deepseek工作\proj03\code
& $py blind.py data\blind\blind_01.wav
```

输出应当包含：

```
文件      : blind_01.wav
基频 f0   : 45.8 Hz
谱心      : 1747 Hz
频段占比  : 低频 0.29 / 中频 0.32 / 高频 0.39
谐波比    : h2 8.83  h3 0.41
判定      : C5 五档 + 半遮挡
依据      : 离 C5 类心 0.42，离次近的 C4 类心 1.87
```

**「离类心多远」这一行必须保留**——它是「模型知道自己有多确定」的证据，也是答辩时最容易被追问的点。

## 5 三条红线（做不到就白拍）

1. **不许剪辑判定过程**。命令敲下去到结果出来，一镜到底。
2. **不许把盲测录音放回训练集**。拍完再放回去可以，但视频里必须能看出「判定发生在加入训练之前」。
3. **不许只拍屏幕**。至少有一次镜头同时拍到风扇实物和屏幕，证明声音是现场来的。

## 6 如果判错了怎么办

**照实拍，然后解释。** 判错比编造可信得多，而且能引出真问题：

- 若把「贴胶带」判成「正常」：说明 2 g 胶带的失衡量还不够，需要加大配重
- 若把「一档」判成「三档」：这正是五分类 66 % 的由来，直接引到方法说明第 4 节

评委看的是「你知不知道自己错在哪」，不是「你有没有错」。
