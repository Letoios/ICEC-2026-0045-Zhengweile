# 数据采集说明

## 设备与环境

| 项 | 内容 |
|---|---|
| 录音设备 | 手机（OnePlus PLK110），系统录音机，mp3 / wav 混用 |
| 采样率 | 48 kHz，单声道 |
| 采样位深 | 16 bit（wav）/ 128 kbps（mp3） |
| 声源 | 台扇一台，五档调速，扇叶可拆卸、网罩可拆 |
| 环境 | 室内，无其他人说话；**后期批次旁边有人敲键盘**，已在异常记录中登记 |
| 录音位置 | 手机距扇叶约 30 cm、离地约 80 cm，指向扇叶中心 |

## 五种工况的定义

| 编号 | 名称 | 具体做法 | 为什么这样定 |
|---|---|---|---|
| **C1** | 一档 | 风扇调最低档 | 低转速基线 |
| **C2** | 三档 | 风扇调中间档 | 中转速基线 |
| **C3** | 五档 | 风扇调最高档 | 高转速基线 |
| **C4** | 五档 + 失衡 | 五档，在**一片扇叶**上贴 2 g 胶带 | 与 C3 只差一个变量（转速相同），学到的才是「失衡」而不是「转速」 |
| **C5** | 五档 + 遮挡 | 五档，用硬纸板挡住**一半进风口** | 同上，只差一个变量 |

**关键设计：C4、C5 都锁定在五档。** 这样「档位」与「故障」两个因素不纠缠。

## 每段录音的规范

- 每段 **10 秒以上**（实际 10.0–26.9 s，中位 11.4 s）
- 每段之间**关机重启**，确保状态可复现
- 开头留 0.3 s、结尾留 0.3 s 作为静音边（分析时会裁掉）
- 文件名前缀按工况编组，导入时按前缀归组

## 已登记的异常与处理

| 编号 | 现象 | 判断 | 处理 |
|---|---|---|---|
| A-01 | 部分批次混用 wav 与 mp3 | 手机录音机默认格式变化 | 统一解码为 48 kHz 单声道 wav，格式差异在解码后消失 |
| A-02 | 部分录音里有键盘声 | 录音时旁边有人敲键盘 | 在频谱上表现为 2–8 kHz 的宽频瞬态；本批未剔除，而是作为「真实环境噪声」保留，正好用于抗噪讨论 |
| A-03 | C3 组的 7 段谱心明显低于同组其余段 | 初判为录音距离变化 | 复核后确认仍是五档，保留；同时记入「档位不可分」的证据链 |
| A-04 | 三段「远近运动」录音 | 录制时刻意改变手机距离 | **不作为训练样本**，单独留作距离鲁棒性测试 |

## 采集脚本

不需要脚本——手机直接录，导出后用 `code/mp3read.py` 或 `code/audio.py` 统一转 wav：

```powershell
& $py -c "import mp3read as M; M.mp3_to_wav(r'原始.mp3', r'输出.wav')"
```

## 复采建议（如果要做第二台设备）

1. 手机固定在支架上，**不要手持**——手持会有 0.1–1 Hz 的晃动调制，污染低频
2. 每段之间记录**手机到扇叶的距离**，最好用卷尺量，因为距离对谱心的影响大于档位
3. 同一工况至少 15 段，且**分 3 次开机**录（避免一次开机录完，覆盖不到冷机/热机差异）
