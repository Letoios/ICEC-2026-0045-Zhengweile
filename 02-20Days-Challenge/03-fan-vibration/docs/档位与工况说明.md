# 五个工况逐个说明与归类

这份文档回答两个问题：**每一档（每一个工况）到底是什么、长什么样**；以及**它们是怎么被归成三类的**。

---

## 一、先说清楚五种工况是怎么造出来的

一台五档小风扇，白色，扇叶可拆。所有录音都在同一张书桌上、同一台手机完成。

| 编号 | 名称 | 怎么做到 | 与谁只差一个变量 |
|---|---|---|---|
| **C1** | 一档 | 按一下开关 | — |
| **C2** | 三档 | 按三下 | — |
| **C3** | 五档 | 按五下（最大风） | — |
| **C4** | 五档 + 扇叶失衡 | 五档，**在一片扇叶上缠一段透明胶带（约 2 g）** | **与 C3 比，只差胶带** |
| **C5** | 五档 + 进风受阻 | 五档，**用打印纸挡住进风面的一半** | **与 C3 比，只差遮挡** |

> 为什么故障都做在五档上：这样 C3 / C4 / C5 三者之间**只差故障本身**，分类器学到的才是「有没有故障」，
> 而不是顺带把「几档」也学进去。

---

## 二、每个工况单独说明（98 段实测）

下表全部来自 `results/features.csv` 的实测中位数，不是估计值。

| | C1 一档 | C2 三档 | C3 五档 | C4 五档+胶带 | C5 五档+遮挡 |
|---|---|---|---|---|---|
| 段数 | 23 | 19 | 23 | 16 | 17 |
| 总时长 | ≈4.4 min | ≈4.1 min | ≈4.8 min | ≈3.2 min | ≈3.4 min |
| **基频 f0 中位** | **33.7 Hz** | **37.4 Hz** | **40.3 Hz** | 42.5 Hz | 45.8 Hz |
| f0 单段范围（10–90 分位） | 27–40 | 31–42 | 36–48 | 31–48 | **46–46** |
| 谱心中位 | 717 Hz | 768 Hz | 749 Hz | 1017 Hz | **1747 Hz** |
| 低频 <500 Hz 占比 | 0.698 | 0.746 | 0.738 | 0.670 | **0.295** |
| 中频 0.5–2k 占比 | 0.129 | 0.110 | 0.117 | 0.122 | **0.319** |
| 高频 >2k 占比 | 0.151 | 0.149 | 0.147 | **0.211** | **0.385** |
| 整段 RMS | 0.028 | 0.070 | 0.089 | 0.094 | **0.019** |
| 二次谐波比 h2 | 1.38 | 1.44 | 1.34 | 1.33 | **8.83** |

### C1 一档
转速最低（约 2020 rpm），风量最小，声音以低频「呼呼」为主，整段 RMS 只有 0.028——比三档低 8 dB 左右。
谱心 717 Hz，三频段里低频占 70%。

### C2 三档
转速升到约 2240 rpm，风量明显上来，RMS 0.070，是 C1 的 2.5 倍。
**谱心 768 Hz 反而比五档（749 Hz）还高一点**——这一条很关键，说明「谱心随档位上升」这个直觉是错的（见第四节）。

### C3 五档
转速最高（约 2420 rpm），RMS 0.089。
与 C1 比，f0 涨了 20%，RMS 涨了 3 倍多，但谱心只涨了 4%——风噪的能量分布并没有随转速线性变亮。

### C4 五档 + 扇叶缠胶带
转速与 C3 相同（f0 42.5 vs 40.3，差异在估计误差内），RMS 略高（0.094 vs 0.089）。
**真正的区别在谐波结构和高频**：
- 每转一圈，多出的那段胶带会多扰动一次气流 → 高频占比 0.147 → **0.211**
- 谱心 749 → **1017 Hz**（这是同档位下唯一显著变化的量）
- 声音听起来从「均匀的风声」变成「带一点嗡嗡的粗糙感」

### C5 五档 + 挡住一半进风口
最特殊的一个，三个维度同时离群：
- **f0 死死钉在 46 Hz**（17 段里 16 段完全一样，范围 46–46）——进风不足后风扇进入一种固定工况
- **RMS 塌到 0.019**（比 C1 还小）——风量掉了，总声级也掉
- **谱心冲到 1747 Hz**、低频占比从 0.74 掉到 **0.295**、h2 从 1.33 跳到 **8.83**

物理上说得通：挡住进风口 → 风量塌 → 低频「呼呼」消失；剩下的是气流挤过半边的缝隙产生的
**高速哨音**，音高稳定、谐波强。所以它不是「更吵」，而是「变了音色」。

## 三、归类：五类怎么归成三类

课题要求交「5 种工况」，但真正的业务问题是「这个风扇正常不正常、是哪种不正常」。
所以评估时同时报三个层次：

| 层次 | 类 | 由哪些组成 | 分组交叉验证 |
|---|---|---|---|
| **五类**（原始） | 一档 / 三档 / 五档 / 胶带 / 遮挡 | C1 / C2 / C3 / C4 / C5 | **61.2 %** |
| **三类**（业务） | 正常 / 失衡 / 遮挡 | C1+C2+C3 合并为「正常」；C4 → 失衡；C5 → 遮挡 | **90.8 %** |
| 二类（最粗） | 正常 / 有故障 | C1+C2+C3 vs C4+C5 | 未单独评估（三类已覆盖） |

**归并规则**（写死在 `code/classify.py` 的 `to3()` 里）：

```
C1, C2, C3  →  正常
C4          →  失衡
C5          →  遮挡
```

**为什么要并**：C1/C2/C3 都正常，只是档位不同。业务上没有人关心「这是几档」，
只关心「它是不是坏了」。把三个正常档合并之后，准确率从 61.2 % 跳到 90.8 %——
**这不是调参调出来的，是问题定义换对了**。

## 四、为什么档位不能当分类目标（关键）

见 `figs/fig07_各档位单独看.png`。三个正常档的 f0 中位数确实在涨：

```
C1 33.7  →  C2 37.4  →  C3 40.3      （约 20%）
```

**但单段估计的范围互相压着**：

```
C1: 27–40     C2: 31–42     C3: 36–48
```

一段一档的录音完全可能算出 40 Hz——正好等于五档的中位数。
两个原因叠加：

1. **单段只有 10–26 秒、约 340–1080 转**，f0 的估计误差就有 ±3–5 Hz 量级；
2. **录音位置每段略有差别**，谱形变化比档位差异还大（见 `docs/方法说明.md` 第 4 节）。

所以「档位分不开」不是特征没选好，是**信息量不够**：
转速差 20% 是真的，但被单段估计误差和位置误差吃掉了。

反过来，**故障**是可以分开的：C5 的 f0 稳定在 46 Hz、h2 高达 8.83、低频占比只剩 0.30；
C4 的高频占比 0.211（正常档都是 0.15 左右）。这些差异**远大于**估计误差。

> 一句话：**档位差 20%，误差也差不多 20%；故障差 2–6 倍，误差盖不住。**

## 五、如果非要做档位识别，需要什么条件

| 条件 | 为什么 | 代价 |
|---|---|---|
| 每段录 60 秒以上 | f0 估计误差从 ±4 Hz 压到 ±1.5 Hz | 98 段要重录 |
| 手机固定在同一个位置 | 消除位置带来的谱形偏移 | 需要支架、每段核对 |
| 每次开机先录一段「基准段」 | 用比值抵消设备与位置差异 | 每工况多录 1 段 |
| 或者干脆用转速计 | 直接测 RPM，不用从声音反推 | 超出「手机内置传感器」的课题边界 |

前三条做完，我们估计五类能到 80 % 以上；但**这已经超出这门课的时间预算**，
所以采取的是「把边界写清楚」而不是「硬凑一个好看的数」。

---

## 六、一句话总结

- **每个档位都单独测了、单独算了特征、单独写了物理成因**（本文第二节）。
- **归类是明确的**：C1/C2/C3 → 正常，C4 → 失衡，C5 → 遮挡（本文第三节）。
- **档位不作为分类目标有硬理由**：差异小于估计误差（本文第四节），不是放弃了没做。
