用 20 天做一个能跑起来、能被追问、能复现的东西。

## 本阶段做了什么

**项目三：基于手机内置传感器的日常旋转机械 / 电器异常声振诊断仪**

用手机麦克风录电风扇在五种工况下的声音，提取时域 / 频域特征，判断「这个风扇正常不正常、是哪种不正常」。

| 项 | 内容 |
|---|---|
| 目录 | [`03-fan-vibration/`](03-fan-vibration/) |
| 数据 | 98 段录音（5 工况 × 16–23 段，共 19.9 分钟） |
| 主结论 | **三类（正常 / 失衡 / 遮挡）分组交叉验证 90.8 %** |
| 次结论 | 五类（含档位）61.2 %——档位本身分不开，已在文档中给出物理解释 |

完整说明见 [`03-fan-vibration/docs/README.md`](03-fan-vibration/docs/README.md)。

## 目录约定

每个项目一个子目录，内部统一用这套结构：

```
03-fan-vibration/
├── README.md / docs/      # 报告与方法说明
├── code/                  # 可执行脚本（包内可直接跑的部分已标注）
├── data/                  # 原始数据（mp3 / wav / 照片 / 视频）
├── results/               # 中间结果（特征表、评估报告、JSON）
├── figs/                  # 图表
├── process_logs/          # 按日过程日志：当天想解决什么、卡在哪、怎么绕过去
└── iterations/            # 版本迭代记录：改了什么、依据是什么、影响多少
```

`process_logs/` 写的是「当时怎么想」，`iterations/` 写的是「后来改了什么」。两者都不做事后美化——
失败的路子也留着（见 `iterations/Iter-03_尝试过但放弃的算法.md`），因为踩过的坑比结论更值钱。
