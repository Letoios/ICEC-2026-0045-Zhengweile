# 2026-10-27　Bug 修复：快节奏下楼被误判成跑步

## 现象

对一段"先下楼、后走路"的连续记录（83.3 s）跑自动分段，输出：

```
0.0 – 26.0 s     跑步      ← 明显不对
26.0 – 70.2 s    下台阶
70.2 – 83.3 s    上台阶
```

用户当场确认：**前面是下楼，后面是走路**。开头根本没有人跑。

## 定位

把第一段的特征打印出来：

```
步频    2.06 – 2.26 Hz
竖直RMS 5.5  – 6.5  m/s²
```

对照训练集里的跑步样本：`步频 2.40 Hz，竖直 RMS 19.05`。

**步频对上了，幅度差 3 倍。**

规则第二条当时是：

```python
if cad > 2.0:  return "跑步"
```

**只看节奏，不看幅度。** 而快节奏下楼时脚与台阶的接触更频繁，步频完全可以冲到 2.2 Hz。

## 修复

```python
# 改前
if cad > T_RUN_CAD:                     return "跑步"

# 改后
if (cad > T_RUN_CAD and rms > T_RUN_MIN) or rms > T_RUN_RMS:
                                        return "跑步"

T_RUN_CAD = 2.0
T_RUN_MIN = 6.0      # 新增：步频高但幅度不够，不算跑步
T_RUN_RMS = 10.0
```

**阈值 6.0 的依据**：训练集跑步段 19.05，其余所有段最高 6.46，两者相差 2.9 倍，中间有很宽的空档，6.0 落在空档里。

## 回归

修复后训练集仍全部判对（8/8），且新样本的开头 26 s 不再被判成跑步。

## 顺带修的第二件事：段内能量跳变

M 段前 26 s 是下楼、后面是走路，但同一标签内部其实没有切开。于是加了一条：

```
同一标签段内，若任意切点前后 4 s 的 RMS 之比 > 1.6，继续切（递归，最多 2 层）
```

M 段由此在 **70.2 s** 处切开：

```
前段 RMS 4.77  →  后段 RMS 2.18
```

与用户描述的"前下楼后走路"一致。

## 教训

**单特征阈值最容易被"另一个特征的极端值"击穿。** 步频高有两种可能：真的在跑，或者动作碎。加一个幅度门槛就能区分。

这类 bug 只有跑**真实连续记录**才会暴露——所有"一段一动作"的测试全绿的时候，它一直躺在代码里。
