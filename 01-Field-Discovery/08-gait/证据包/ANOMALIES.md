# 异常数据登记册（ANOMALIES）

> 面试维度一说的是"**追问采样边界、异常数据原因及排障细节**"。
> 这份册子就是那些"细节"的答案。
>
> 一条原则：**能编出漂亮结果的人很多，能说清自己哪里错了的人很少。**
> 这本册子记录的全是没解决或只是部分解决的问题——它是这份材料里最硬的部分。

## A-01　跑步样本贴住量程上限

| 项 | 内容 |
|---|---|
| **样本** | `run`（2026-10-24 18:03:23，28.3 s） |
| **现象** | 合加速度峰值 `max\|a\| = 82.61 m/s² = 8.42 g` |
| **排查** | 查手机传感器量程：默认 ±8 g。8.42 g 已越过边界，说明**峰值被削掉了**。 |
| **结论** | 该样本的峰值特征不可信；RMS 受影响较小（削顶只影响极少数采样点）。 |
| **影响与处置** | 跑步的判据用的是 RMS（19.05）和步频（2.40 Hz），都是稳健统计量，所以最终判定仍然正确。**但如果今后要分析冲击强度，这个样本必须重录。** 已在待办里记录：跑步需用 ±16 g 量程重录。 |

## A-02　重力方向估错，竖直加速度偏差 37%

| 项 | 内容 |
|---|---|
| **样本** | 全部早期样本 |
| **现象** | 同一条上楼梯记录，竖直 RMS 算出 2.59，判定"平地慢走"，与目视不符。 |
| **排查** | 早期用"整段三轴均值"当重力方向。但人在上楼时每个周期都有净向上的加速，这些分量会累加进均值，把重力方向拉偏。 |
| **修正** | 改用 Phyphox 融合输出的 `Gravity`，并用 `np.interp` **按时间列**把 200 Hz 重力插值到 480 Hz 加速度上（不能按行号对齐，行数不同）。 |
| **结果** | 竖直 RMS：2.59 → **3.56**（+37%）；判定：平地慢走 → **上台阶**。 |
| **影响与处置** | 这是影响面最大的一次修正——**所有样本必须用同一条管线重算**，两批不同管线的数字不可横向比较。这条已写进方法文档首条。 |

## A-03　首尾磕碰被误判成动作

| 项 | 内容 |
|---|---|
| **样本** | 连续记录（83.3 s，先走路后下楼） |
| **现象** | 前 3 秒被判成"下台阶"，偏度 0.85。 |
| **排查** | 对波形：那 3 秒是一串无规律的冲击尖峰，没有周期性——是**手机刚被握稳时磕到了手**。 |
| **修正** | `trim_ends(head=3.0, tail=2.0)`：先固定裁首尾；再检查首尾 6 s 内是否还有 0.25 s 窗峰值超过全段中位峰值 2.5 倍，有就继续外裁（最多 6 s）。 |
| **结果** | 该段切分变为 `3.0–16.2 走路 / 16.2–21.7 过渡 / 21.7–83.3 下楼`，与手工判读一致。一致率 76% → 79%。 |
| **影响与处置** | **首尾污染是系统性现象，不是偶发**——每次装/取手机都会产生。已固化为预处理必经步骤。 |

## A-04　快节奏下楼被判成跑步（真 bug）

| 项 | 内容 |
|---|---|
| **样本** | 连续记录（83.3 s）开头 26 s |
| **现象** | 判成"跑步"。但现场根本没有人跑。 |
| **排查** | 打印特征：步频 2.06–2.26 Hz，竖直 RMS 仅 5.5–6.5。对照训练集跑步样本：步频 2.40 Hz、RMS **19.05**。**步频对上了，幅度差 3 倍。** |
| **根因** | 跑步判据当时是 `if cad > 2.0 → 跑步`，**只看节奏不看幅度**。快节奏下楼时脚与台阶接触频繁，步频可以冲到 2.2 Hz。 |
| **修正** | 改为 `if (cad > 2.0 and rms > 6.0) or rms > 10.0`。阈值 6.0 的依据：跑步段 19.05，其余所有段最高 6.46，两者相差 2.9 倍，6.0 落在空档里。 |
| **结果** | 该段不再判成跑步；训练集回归全部正确。 |
| **影响与处置** | **单特征阈值最容易被另一个特征的极端值击穿。** 这类 bug 只在跑真实连续记录时才暴露——所有"一段一动作"的测试全绿时，它一直躺在代码里。 |

## A-05　慢速平地走被判成上台阶（**原因未查明**）

| 项 | 内容 |
|---|---|
| **样本** | `E`（平地慢走，手持正常摆臂，与同批其余走路段条件相同） |
| **现象** | 判成"上台阶"，滑窗一致率仅 51%，中位余量 0.00。 |
| **排查** | 归一化后的波形里布满窄尖峰，与同批两段走路差异明显：自相关只有 0.63（`J` 0.72、`H2` 0.88），偏度冲到 +1.23（`J` +0.18、`H2` −0.26）。正负峰占比被这些尖峰推到 +0.040，越过下楼门槛；同时自相关没过 0.70，最终掉进上台阶兜底。**但该段录制时没有单独记录条件，事后无法复现当时的握持与步态细节。** |
| **结论** | **原因未明。** 已排除"携带方式不当"这一解释（全部样本均为手持摆臂录制）。能确定的只有：同是摆臂慢走，`J` 判对、`E` 判错，说明慢速行走这一档本身就不稳定。 |
| **影响与处置** | 不靠调阈值解决——任何能让 `E` 判对的改动都会让 `J` 或 `X` 判错（见 `2026-10-28_阈值参数扫描`）。作为**已知失效**如实记录，n=1，只写"观察到失效"，不写成统计结论。 |

## A-06　端握不摆臂被判成下台阶

| 项 | 内容 |
|---|---|
| **样本** | `P`（平地慢走，手机**握在手里但不摆臂**） |
| **现象** | 判成"下台阶"，一致率 53.1%。 |
| **排查** | 手臂不动时，手机只感受到躯干的上下一两次起伏；走路的双峰节律消失，波形退化成一串不对称的小毛刺，偏度与正负峰占比都失真。 |
| **结论** | **真正决定信号质量的是"手臂是否摆动"，而不是手机怎么拿。** 16 段手持摆臂样本中判对 13 段（覆盖慢走、常速走与上下楼），端握不摆臂这一段判错。 |
| **影响与处置** | 适用条件从"手机拿在手里"收紧为"**手机随手臂摆动**"。这一条是本人亲自纠正 AI 的分类口径后得出的（AI 原本按"手提还是握着"分，是错误维度）。**n=1，同样只能写"观察到失效"。** |

## A-07　快节奏上楼被判成平地走（**尚未解决**）

| 项 | 内容 |
|---|---|
| **样本** | `H`（上台阶，步频 1.63 Hz） |
| **现象** | 判成"平地走"。**而且滑窗一致率高达 94.8%**——37 个窗里 35 个都同意这个错误答案。 |
| **排查** | ① 查库里的上楼样本：三段全是 1.30 / 1.30 / 1.39 Hz，**没有一段是快节奏的**；② 该样本自相关 0.77，刚好越过走路门槛 0.70；③ 用 5 个特征做标准化最近邻：到"上楼 c"距离 1.07、到"平地走"1.08——**几乎等距**；④ 尝试用 FFT 二次谐波比区分：走路 0.07、快上楼 0.05，**不可分**。 |
| **结论** | 这是**采样偏差**，不是算法缺陷。规则从三段慢速上楼里学到的是"上楼 = 不规整"，一旦来了规整的快上楼就被归给走路。 |
| **影响与处置** | **未解决。** 解法只有补样本（录 2 段快节奏上楼）。在补到之前，这一条明确写进文档的"已知失效"。 |
| **附带发现** | 该样本的**中位余量只有 0.07（全场最低）**，而一致率 94.8%（全场最高）。→ **一致率骗人，余量不骗人**。这条观察直接否掉了"用一致率做置信度红绿灯"的原方案。 |
