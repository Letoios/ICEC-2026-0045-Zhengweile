## 二、怎么自己验证（三步，三分钟）

**① 看时间戳**

把 `08课题运动原始文件现场/跑步 2026-10-24 18-04-02(1).zip` 解压，打开 `meta/time.csv`，第一行是：

```
"event","experiment time","system time","system time text"
"START",0.000000000E0,1792836203.368,"2026-10-24 18:03:23.368 UTC+08:00"
```

`system time text` 是**手机操作系统在按下"开始"那一刻的时钟**，由 Phyphox 直接读取系统时间写入，不是人工填写。

**② 看设备**

同一个 zip 里的 `meta/device.csv`：

```
"deviceModel","PLK110"
"deviceBrand","OnePlus"
"deviceBoard","canoe"
"accelerometer Name","lsm6dsv Accelerometer Non-wakeup"
```

**③ 看数据能不能对上**

`Accelerometer.csv` 的行数 ÷ 采样率 = 时长，必须与 `meta/time.csv` 里 START 到 PAUSE 的时间差一致：

| 交付目录 | 加速度行数 | 行数 ÷ 480 | 与 meta 时间差 |
|---|---|---|---|
| `01_still` | 24,587 | 51.2 s | 51.2 s ✓ |
| `03_run` | 13,591 | 28.3 s | 28.3 s ✓ |
| `04_stairs_up` | 23,567 | 49.1 s | 49.1 s ✓ |
| `05_stairs_down` | 31,157 | 64.9 s | 64.9 s ✓ |

**行数、时长、时间戳三样互相咬合，缺一样都造不出来。**

## 三、为什么这能证明"是本人真实采集"

**第一，时间分布符合真实作息，不符合造数据的习惯。**

造数据的人会让时间戳整齐：全一样，或者整点、整分。实际是：

```
17:54:17  →  17:59:31  →  18:03:23      （10-24 傍晚，走路→静止→跑步）
次日 15:41:41  ←  15:38:11              （10-25 下午，先下楼再上楼）
```

**跨两天、跨傍晚与下午、中间有 5 分钟的走路换场间隔**，这是一个人拿手机在校园里跑来跑去的自然节奏。

**第二，下楼比上楼早 3 分 30 秒。**

10-25 那次先录 `下楼`（15:38:11），3 分半后录 `上楼梯`（15:41:41）。真实场景就是：从楼上下来 → 走到另一侧楼梯 → 再上去。这个顺序和间隔，编不出来。

**第三，文件指纹可交叉核验。**

每段 `Accelerometer.csv` 的 SHA256 前 16 位已写在配套 CSV 里。`data/` 里的交付文件与 zip 内的字节**完全一致**（已逐字节比对），说明交付数据是从这些原始录制里原样取出来的，中间没有被替换或重新生成。

**第四，传感器型号是硬件级的。**

`lsm6dsv` 是这颗手机主板上实际焊的加速度计芯片型号，随设备走，不随 App 走。换一台手机，这个字段就不一样。
