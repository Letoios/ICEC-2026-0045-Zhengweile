# 2026-10-26　修正：改用 Gravity 数据按时间插值

## 现象

换了测试设置，导出的文件里多了 `Gravity` 和 `Orientation` 两份传感器数据。

同一条上楼梯记录，用旧方法（整段均值估重力）算出来：

```
竖直 RMS = 2.59
峰率     = 1.19 Hz
判定     = 平地慢走
```

但我明确记得那是在上楼。**数算错了，不是动作错了。**

## 排查

1. 先怀疑是数据对齐问题。查三份文件的采样率：
   - `Accelerometer.csv` 480 Hz
   - `Gravity.csv` 200 Hz
   - `Orientation.csv` 240 Hz
   
   **三者行数完全不同**，如果按行号取重力，第 N 行对应的根本不是同一时刻。

2. 再检查 Phyphox 的 `Gravity` 到底是什么。它的模长统计：

```
|g| = 9.81 ± 0.00   （全程恒定）
```

→ 这是一个由加速度计 + 陀螺仪**融合后归一化的重力方向矢量**，不是原始测量值。正因如此它恒定，反而说明它可信。

3. 反观"整段均值"：人在上楼时，每个动作周期都有一个净向上的加速阶段，这些分量会累加进均值里，把重力方向拉偏。

## 修正

```python
# 按时间列插值，不是按行号
gx = np.interp(t_acc, t_grav, grav_x)
gy = np.interp(t_acc, t_grav, grav_y)
gz = np.interp(t_acc, t_grav, grav_z)
gn = np.sqrt(gx**2 + gy**2 + gz**2)
v  = (ax*gx + ay*gy + az*gz) / gn      # 竖直分量
```

## 结果

| 项 | 均值估重力 | Gravity 插值 | 差异 |
|---|---|---|---|
| 竖直 RMS | 2.59 | **3.56** | +37% |
| 峰率 | 1.19 Hz | **1.30 Hz** | +9% |
| 判定 | 平地慢走 ✗ | **上台阶 ✓** | 翻转 |

复核其他量：`|a|>20 m/s²` 占比 0.19%，正峰 5.25 / 负峰 −6.04 —— 与"缓慢蹬起、对称"的上楼形态一致。

## 教训（写进了方法文档）

1. **竖直投影必须按时间列插值对齐**，不同传感器的采样率天生不同，按行号对齐会引入随机的时移。
2. **"恒定"不等于"没用"**：`|g|` 恒为 9.81 看起来像无效数据，但它正是融合算法的输出，比任何自估方法都稳。
3. **两批数据不能用不同管线算完再横比**。旧批次的数值是均值估重力算的，新批次用 Gravity 算的，混在一张表里比较没有意义。

第 3 条直接决定了后来的做法：**所有样本用同一条管线重算一遍**，才允许出现在同一张表里。
