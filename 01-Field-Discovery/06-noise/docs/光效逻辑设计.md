# 课题 06　校园声学超标自动提醒 —— 光效逻辑设计

> 一套可以直接落地实现的分级光效规则：**测什么 · 怎么判 · 亮什么 · 何时切**

| 判定依据 | 控制对象 | 输出形态 |
|---|---|---|
| GB 3096-2008 | 5 点位 × 3 时段，共 15 组实测 | 颜色 + 频率，双通道 |

---

## 1　为什么要做这个

校园噪声有一个天然矛盾：**声音「听得见」，超标「看不见」**。

分贝计 App 读完一个数字就关掉了，噪声地图是事后画的；现场的人 —— 正在自习的同学、路过的老师 —— 并不知道自己此刻处在 70 dB 还是 50 dB 的环境里。本设计要补的正是这「最后一米」：把「测量 → 判定 → 提示」这条链路的末端，做成一个抬头就能看懂的光效装置，让声环境状态像红绿灯一样直白。

本设计的数据底座是同一课题的 15 组实测（见《数据分析说明》）。**所有阈值都从这 15 组数据里标定出来，不是拍脑袋定的。**

### 四条设计原则

1. **实时优先。** 1 s 刷新，状态切换不超过 3 s，避免「人都走了灯才红」。
2. **可读优先于精确。** 光效只回答一个问题 —— 现在吵不吵、吵到什么程度；具体数值交给数据表与手机端。
3. **不制造新污染。** 夜间主动压暗、限频，不把「噪声提醒」做成「光污染」。
4. **一套逻辑走完全部点位。** 用「相对限值的偏移量」而非绝对分贝分级，1 类图书馆与 4a 类主干道共用同一套参数。

---

## 2　判什么：先把「超标」定义清楚

判定量取 **Δ = Leq − 适用限值**，而不是绝对声级。理由在《数据分析说明》第 5 节：五个点位分属 1 类 / 2 类 / 4a 类，限值从 55 到 70 不等，只有换算成 Δ 之后，五个方向才能用同一把尺子。

实测 15 组的 Δ 分布：

```
−12.7 ──────────────  0  ──────────────  +15.1
 ↑ 主干道中            ↑ 限值线           ↑ 图书馆晚
  （最安静的一组）                          （最超标的一组）
```

**关键事实：15 组里有 13 组的 Δ 为正，夜间 5 组全部为正，最大 +15.1 dB。** 这意味着如果照搬「超标就红」，这个灯在校园里几乎永远是红的 —— 红灯会失去信息量。所以下面第 5 节专门处理「常态超标」这件事。

### 峰值为什么另开一条通道

Leq 是能量平均值，会把一次 0.2 s 的尖叫、一声急刹抹平（实测：中午食堂整段 Leq 64.0 dB，但瞬时峰值到过 74.3 dB，1 s 峰值 69.8 dB）。真实场景里最扰人的恰恰是这类瞬时冲击。

所以单独开一条通道：**Lmax ≥ 85 dB(A) 立即触发冲击提示**，不参与平滑、不排队去抖，3 s 后自动回退到当前等级。

85 dB(A) 的取法：GBZ 2.2 将 85 dB(A) 作为 8 h 等效声级的职业接触限值。校园虽非职业场所，但瞬时达到该量级已足以引起惊吓与听觉不适，作为「冲击」红线是合适的；同时它高于所有功能区限值，不会与等级判定混淆。

## 3　怎么判：五级分区

| 状态 | 判据 | 主观感受 | 处置建议 |
|---|---|---|---|
| S0 安静 | Δ ≤ −10 | 接近背景噪声 | 维持，按周期复测 |
| S1 达标 | −10 < Δ ≤ 0 | 正常交谈无需提高音量 | 维持 |
| S2 轻度超标 | 0 < Δ ≤ +5 | 需略微提高音量 | 排查单一噪声源，限时整改 |
| S3 中度超标 | +5 < Δ ≤ +10 | 交谈吃力、难以专注 | 行为管控 + 隔声/吸声措施 |
| S4 重度超标 | Δ > +10 | 需喊话，久留不适 | 立即干预，必要时调整功能布局 |

**为什么取 5 dB 一档？** 人对响度的主观感受大致按 3—5 dB 一个台阶变化：3 dB 才能稳定听出「响了一点」，5 dB 是「明显更吵」，10 dB 相当于响度翻倍。以 5 dB 分档，恰好对应「刚超标 / 明显超标 / 严重超标」三种可感知程度。

**这个分档和实测数据是吻合的**：15 组里 S2 有 4 组、S3 有 4 组、S4 有 5 组、达标 2 组 —— 五档全部用上了，没有出现「某一档永远为空」的退化情况。

## 4　亮什么：颜色 + 频率双通道

| 状态 | 主色 | RGB | 亮度 | 闪烁频率 | 占空比 | 占空比与光效描述 |
|---|---|---|---|---|---|---|
| S0 安静 | 青蓝 | `#00C2FF` | 25% | 常亮 | 100% | 低亮度常亮，最不打扰 |
| S1 达标 | 绿 | `#22C55E` | 50% | 常亮 | 100% | 中亮度常亮 |
| S2 轻度 | 黄 | `#FACC15` | 75% | 呼吸 0.5 Hz | 50% | 缓慢明暗起伏 |
| S3 中度 | 橙 | `#FB923C` | 90% | 闪烁 1.0 Hz | 50% | 亮暗各半 |
| S4 重度 | 红 | `#EF4444` | 100% | 急闪 2.5 Hz | 30% | 短促强闪 |
| SP 冲击 | 红白 | `#EF4444` | 100% | 快闪 5.0 Hz | 50% | 红白交替 3 s |

**只用颜色分级有一个硬伤**：红绿色觉障碍者约占男性人口的 8%，红、绿、橙在他们眼中高度接近，五级色阶实际退化为两三档。因此采用「颜色 + 闪烁频率」双通道 —— 即使颜色分辨不出，频率梯度依然可读：越吵闪得越快，从常亮一路到 5 Hz 急闪。

### 几个刻意的取舍

- **常亮优先。** 达标与安静用常亮，只有超标才闪。闪烁本身就是「异常」信号，若平时也在闪，信号就贬值了。
- **频率单调。** 0.5 → 1.0 → 2.5 → 5.0 Hz 单调递增，中间不设回退，保证「更快 = 更吵」的直觉成立。
- **占空比递减。** 重度超标用 30% 占空比，短促强闪比长亮更「刺」，视觉冲击更强。
- **冲击态红白交替**，与 S4 的纯红拉开距离，避免「到底是重度超标，还是一次关门声」分不清。

## 5　何时切：状态机与三条刹车

### 5.1　六个状态

S0 安静、S1 达标、S2 轻度、S3 中度、S4 重度，构成一条有序链；**SP 瞬时冲击游离于链外**，可由任意状态直接触发。

### 5.2　迁移规则

| 当前状态 | 触发条件 | 目标状态 | 备注 |
|---|---|---|---|
| 任意 | Lmax ≥ 85 dB(A) | SP | 瞬时触发，不参与平滑与去抖 |
| SP | 持续 3 s 结束 | 回退至当前等级 | 回退后重新判定 |
| S0—S4 | 升高至更高档，且持续 3 s | 对应更高档 | 即时切换，无延迟 |
| S2—S4 | 低于低一档阈值 2 dB，且持续 5 s | 低一档 | 回差 + 保持双条件 |
| 任意超标态 | 未满 10 s | 维持原状态 | 最短保持，防闪灯疲劳 |

### 5.3　三条刹车：为什么必须加

三个参数解决同一个问题：**灯在阈值附近疯狂跳变**。

1. **去抖 3 s** —— 新等级必须连续 3 个采样周期成立才切换。人的喊声、椅子拖动通常短于 1 s，被自然滤掉。
2. **回差 2 dB** —— 降级要求 Δ 低于下一档阈值 2 dB，而不是刚好低于。例如从 S3 回 S2，需要 Δ < 3，而非 5。
3. **保持 10 s** —— 任一超标态至少维持 10 s。否则一次 3 s 的咳嗽会让灯闪一下又灭，看起来像故障。

三者叠加后的实际表现：稳定状态几乎不闪；真实变化在 3—5 s 内完成响应；临界抖动完全不响应。

### 5.4　优先级仲裁

```
SP  >  S4  >  S3  >  S2  >  S1  >  S0
```

高优先级可立即抢占；低优先级不得覆盖高优先级，必须等高优先级满足退出条件后才能接管。这条规则防止「冲击提示还没走完，就被等级判定刷掉」。

## 6　夜间怎么办：这是本设计最要紧的一节

### 6.1　数据说了什么

夜间 5 组全部超标，Δ 从 +5.3 到 +15.1。但同一批点位，夜间声级只比早间变化 **−3.1 ~ +1.6 dB** —— 夜里并没有更吵，是限值整整降了 10 dB。

这不是采集问题，是 GB 3096 的真实规定。但它对提醒装置是致命的：

> **22:00 一到，所有灯会因为限值换挡而集体由绿跳红；此后一直红着，红到天亮。**

一盏永远红的灯，等于没有灯。

### 6.2　三条应对

**① 换挡时用渐变，不用跳变。**
22:00 与 6:00 两个切换点，颜色在 3 s 内线性过渡，不闪、不闹、不鸣。制度性变化不该用告警的方式表达。

**② 夜间主看「增量」，不看「绝对值」。**
夜间 Δ 已经 +13，再涨 2 dB 还是红，信息量为零。所以夜间改判 **相对本点位夜间基线的增量 δ**：

```
δ = Leq(当前 10 s) − Leq(本点位夜间基线)
δ ≥ +3 dB  →  判定为「变吵了」，用呼吸频率加快表达，不换颜色
δ ≤ −3 dB  →  判定为「安静下来了」，频率放慢
```

夜间基线在第一次进入夜间模式时用前 60 s 现场实测建立（每个点位一个值），存在本地，断电不丢。

**③ 主动压暗、限频。**
夜间亮度 ×0.4、闪烁频率上限 1 Hz。理由很简单：一个装在走廊或宿舍楼下的提醒灯，夜间全亮闪烁等于制造新的光污染，甚至影响睡眠 —— 用「治理噪声」的手段制造「光噪声」，逻辑上说不通。夜间策略是「提醒但不打扰」：以常亮或低频呼吸为主。

### 6.3　昼间 / 夜间参数对照

| 参数 | 昼间 6:00—22:00 | 夜间 22:00—6:00 |
|---|---|---|
| 判定限值 L | 昼间值（1 类 55 / 2 类 60 / 4a 类 70） | 夜间值（1 类 45 / 2 类 50 / 4a 类 55） |
| 整体亮度系数 | 1.0 | 0.4 |
| 闪烁频率上限 | 5.0 Hz（冲击态） | 1.0 Hz |
| 光效偏好 | 闪烁为主，强调警示 | 常亮 / 低频呼吸为主，强调不打扰 |
| 模式切换时刻 | 06:00 | 22:00 |
| 判定主轴 | Δ（相对限值） | δ（相对本点位夜间基线） |

## 7　仪器本身有偏差，判据要留灰带

手机麦克风没有接标准声级计，实测偏差不小（详见《数据分析说明》第 4 节：自动校准偏移跨 22.35 dB，两套 App 互差 −5.6 ~ +15.4 dB）。所以判据不能是「一根线」，而应是一条带：

```
|Δ| < 3 dB  →  判定为「不确定」，光效取黄绿之间（S1/S2 之间呼吸），并标记「待复核」
```

按这条规则重算 15 组：**确定超标 10 组、确定达标 2 组、不确定 3 组**（早食堂 +2.5、早运动场 +1.5、中运动场 +0.8）。也就是说，13 个超标结论里有 3 个是「贴着线」的，换台手机就可能翻转 —— 这一点必须写在报告里，而不是假装它不存在。

## 8　怎么做：三档实现方案

| 方案 | 组成 | 成本 | 适用场景 |
|---|---|---|---|
| **A 真机原型** | ESP32-C3 + INMP441（I2S 数字麦）+ WS2812B 8 灯环 + DS3231 时钟 + 3D 打印外壳 | 约 120—180 元 | 答辩实物演示、点位长期布设 |
| **B 零硬件** | 手机分贝计 App 连续采样 + 手机补光灯 / 屏幕取色，用快捷指令或 Tasker 串接 | 0 元 | 先验证逻辑，不占用采购时间 |
| **C 课堂演示** | PC + Python（sounddevice 实时取声）+ 屏幕色块 | 0 元 | 讲解状态机与阈值曲线 |

答辩实物演示建议 A 档，前期验证逻辑用 B 档即可。

**校准是绕不过去的一步**：手机或驻极体麦克风的个体差异可达 ±4 dB，必须先用 94 dB / 1 kHz 声校准器、或与标准声级计同点比对，把偏差作为 offset 写进代码。否则「55 dB 报警」可能实际发生在 51 或 59 dB，整套阈值的意义就没了 —— 这正是《数据分析说明》第 4 节要专门交代不确定度的原因。

## 9　核心处理流程

```text
每 1 s 执行一次：
    raw  = 读取当前 A 计权声级
    leq  = 0.3 * raw + 0.7 * leq_prev      # 指数平滑，抑制毛刺
    lmax = 读取本周期峰值                   # 不平滑，保留瞬时性
    L    = 限值(点位功能区, 是否夜间)        # 昼间/夜间自动切换

    # ① 冲击通道（最高优先）
    if lmax >= 85:
        sp_until = now + 3s

    # ② 等级判定
    level = 分级(leq, L)                    # 返回 S0 ~ S4

    # ③ 仲裁
    if now < sp_until:
        state = SP
    elif level > state:
        if 连续满足 3 次: state = level       # 上升沿：即时
    elif level < state:
        if leq < 阈值(state → level) - 2 and 持续5s and 已保持10s:
            state = level                    # 下降沿：回差 + 保持

    输出光效(state, 夜间亮度系数)
```

两点说明：其一，平滑只作用于 Leq，不作用于 Lmax —— 冲击必须保留「瞬时」属性。其二，状态比较使用等级序号而非分贝值，后续要加档位（例如按 2.5 dB 细分）时不必改动比较逻辑。

## 10　怎么验证：8 条验收用例

| 编号 | 输入场景 | 预期光效 | 判定要点 |
|---|---|---|---|
| T1 | 1 类区昼间，稳态 50 dB | 绿色常亮（S1） | 基础分级正确 |
| T2 | 稳态 58 dB | 黄色 0.5 Hz 呼吸（S2） | 跨一档判定正确 |
| T3 | 稳态 62 dB | 橙色 1.0 Hz 闪烁（S3） | 跨两档判定正确 |
| T4 | 稳态 70 dB | 红色 2.5 Hz 急闪（S4） | 上限档判定正确 |
| T5 | 单次 90 dB 脉冲 0.5 s | 红白快闪 3 s 后回原档 | 冲击通道独立生效 |
| T6 | 55 dB 上下 ±0.5 dB 抖动 30 s | 状态全程不变 | 回差与去抖生效 |
| T7 | 22:30 稳态 58 dB | 红色但亮度 40%、频率 ≤1 Hz | 夜间模式生效 |
| T8 | 断电重启 | 默认 S0，10 s 内完成自检 | 故障安全 |

其中 T6（阈值抖动）与 T7（夜间模式）最容易漏测，却恰恰决定了这套逻辑「稳不稳、能不能长期挂着」。

**验收标准**：8 条全部通过；连续运行 2 h 无死机、无状态卡死；日志可导出，且与数据表口径一致。

## 11　与数据表、雷达图的对应关系

三件交付物其实是同一套阈值的三种用法：

- **数据表** —— 离线、逐点、可存档，回答「哪个点位、哪个时段超标」。
- **雷达图** —— 空间与时间的整体画像，回答「哪里最吵、什么时候最吵」。
- **光效逻辑** —— 在线、实时、就地，回答「现在吵不吵」。

数据表的「判定」列与本设计第 3 节的判据完全同源；雷达图上最外凸的点位（本组数据中为图书馆晚 +15.1、实训室走廊晚 +14.2、运动场晚 +13.1），就是光效装置最该优先布设的位置。**把有限的灯装在雷达图的外圈上**，是这个课题最直接的一条落地建议。
