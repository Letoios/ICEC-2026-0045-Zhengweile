# 课题 06　真实性证据包

> 目的：任何人拿到这个文件夹，都能**从原始字节开始**，把 15 组结论重新算一遍，并核对「这些数据确实是本人在这些时刻、用这台设备采的」。

---

## 1　包里有什么

| 文件 / 目录 | 作用 |
|---|---|
| `采集证明_设备时间与设备型号.csv` | **核心表**。15 行，每行一个测点：设备型号、系统起止时间（精确到毫秒）、自动校准偏移、原始 zip 的 SHA256、现场照片清单、双源对照值 |
| `采集证明_验证说明.md` | 这份证据怎么用、能证明什么、不能证明什么 |
| `本人完成说明.md` | 本人完成情况与分工声明 |
| `ANOMALIES.md` | 异常登记（A-01 ~ A-07），包括口径争议、机型不一致、校准跨度 |
| `process_logs/` | 按日期的过程记录（7 份），记录当时为什么这么采、遇到什么问题 |
| `raw_output/extract_15组.txt` | 15 组指标重算的纯文本输出，可与 Excel 逐行对照 |

原始数据副本不在本包内，在上一层的 `../data/` 里：每组一个目录，含 `Amplitudes.csv`（Phyphox 原始 20 Hz 序列）+ `meta.txt`（设备、时间、偏移、SHA256、指标）。

---

## 2　三条可核验的链条

### 链条一：文件指纹 —— 证明「数据没被改过」

`采集证明_设备时间与设备型号.csv` 里每一行都有 `zip SHA256`。核验方法：

```powershell
Get-FileHash "D:\分贝项目\早图书馆\声音振幅 2026-10-27 08-19-38.zip" -Algorithm SHA256
```

算出来的 64 位十六进制串必须与表里 `zip SHA256` 一列**逐字符相同**。任何一个字节被改动，哈希值就会完全不同。

同时 `raw_output/extract_15组.txt` 是从原始 CSV 重算出来的指标，Excel 里的数字应与它一致。

### 链条二：设备时间 —— 证明「什么时候采的」

Phyphox 的每个 zip 里都有 `meta/time.csv`，记录 START / PAUSE 两个事件的系统时间，格式精确到毫秒，带时区：

```
"START",0.000000000E0,1793060383.482,"2026-10-27 08:19:43.482 UTC+08:00"
"PAUSE",9.009391372E1,1793060473.576,"2026-10-27 08:21:13.576 UTC+08:00"
```

这个时间不只是「我们写了什么」，它是**手机操作系统在录制开始那一刻打的戳**，并且与现场照片的 EXIF 拍摄时间、与另一款 App 的 `Transfer Dock_Text_*.txt` 里的毫秒时间戳可以三方对照。

### 链条三：设备型号 —— 证明「用哪台设备采的」

同一个 zip 里的 `meta/device.csv`：

```
"deviceModel","PLK110"
"deviceBrand","OnePlus"
"version","1.2.1"
"build","1020105"
"fileFormat","1.20"
```

15 组里 14 组是 PLK110，1 组（晚上图书馆）是 PKG110 —— 这个不一致**没有被抹平**，原样登记在表里并写进 `ANOMALIES.md` 的 A-01。

## 3　怎么在 3 分钟内自证

```powershell
# 1) 看证书表
Import-Csv "采集证明_设备时间与设备型号.csv" | Format-Table 编号,时段,监测点位,设备型号,"开始时刻(系统时间)","自动校准偏移(dB)",判定 -AutoSize

# 2) 抽查任意一个 zip 的哈希
Get-FileHash "D:\分贝项目\晚上食堂\声音振幅 2026-10-26 19-13-33.zip" -Algorithm SHA256

# 3) 打开原始 zip 里的 meta/time.csv 与 meta/device.csv，与第 1 步的表对一遍

# 4) 打开 raw_output/extract_15组.txt，与 Excel 的 01 页逐行对一遍
```

四步走完，数据「是不是这批」、「什么时候采的」、「哪台机器采的」、「指标算得对不对」四件事就都能落地。

## 4　这份证据包**不能**证明什么

必须提前说清楚，避免答辩时被当成硬伤：

1. **不能证明「绝对声级准」**。手机麦克风未接标准声级计，自动校准偏移跨度 22.35 dB，两套 App 互差最大 15.4 dB（详见 `ANOMALIES.md` A-02 / A-03 与 `../docs/数据分析说明.md` 第 4 节）。
2. **不能证明「点位代表性」**。每组只有 1~2 分钟，反映的是那两分钟的声环境，不是全天平均。
3. **不能证明「晚上图书馆那一段与其他段同机同参」**。机型不同（A-01），虽同为 OnePlus、同版本 Phyphox，但未做机型间标定。

**这三条限制反而构成了《创新体系》的出发点**：正因为绝对量不可信，才把判据改成「相对限值的偏移量 + 区间判定」；正因为样本短，才把光效设计成「看变化量而不是看绝对值」。
