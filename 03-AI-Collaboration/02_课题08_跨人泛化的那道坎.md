# 02 · 课题08：跨人泛化那道坎

课题 08 要求「采集平地慢走、快跑、上下楼梯、静止四种状态，提炼区分动作的阈值规则」。

这段经历里最值得记的不是「34 段全对」，而是**全对之后发生的事**：
换两个人来测，准确率掉到 3/6。这一篇记五个节点。

---

## 案 1｜重力投影：用「整段均值」估重力，判错了一段

**问题**：第一版拿到的是旧格式导出（只有 `Accelerometer.csv`，没有重力文件）。
我的做法是「整段三轴均值 ≈ 重力方向」，把加速度投影到竖直方向。

**我的提问**：「这样估重力行不行？」

**AI 的回答**：先看 `|g|` 是不是 9.8。如果整段均值算出来的模长明显偏离 9.8，说明人动得厉害、均值不等于重力。

**我做的验证**：拿一段已知是「上台阶」的录音（`啥.zip`）算：
- 均值估重力 → 竖直 RMS **2.59**、步频 1.19 Hz → 判「平地慢走」；
- 改用文件里真正的 `Gravity.csv`、按时间戳 `np.interp` 插值对齐 → 竖直 RMS **3.56**、步频 1.30 Hz → 判「上台阶」。

**结论**：**同一段数据，两种重力估计，判定翻转。**
差 37% 的 RMS 全部来自「把人的动态加速度混进了重力估计」。
从此立了一条规矩：**竖直投影必须用 `Gravity.csv` 按时间列插值对齐，不能按行号对齐**
（加速度 480 Hz、重力 200 Hz、姿态 240 Hz，三条流采样率不同）。

---

## 案 2｜跨人测试：3/6，而且错得很有规律

**问题**：本人 8 段训练完，全部判对。找两位同学各录 3 段（走 / 上 / 下），盲测。

**结果（旧规则）**：

| 真值 | 判定 | 自相关 | 说明 |
|---|---|---|---|
| 男同学·走路 | 上台阶 ✗ | 0.57 | |
| 女同学·走路 | 上台阶 ✗ | 0.64 | |
| 女同学·下楼 | 下台阶 ✓ | 0.68 | |
| 女同学·上楼 | 无法判定 ✗ | 0.35 | 掉进「信息量不足」分支 |
| 男同学·下楼 | 下台阶 ✓ | 0.69 | |
| 男同学·上楼 | 上台阶 ✓ | 0.52 | |

**我的提问**：「错的两段都是走路，为什么？」

**AI 的回答**：看自相关这个特征是什么。它是「波形前后重复程度」——
对同一个人，走路可能 0.88（正常走），也可能 0.56（慢走）；对两个人，上楼 0.35 / 0.52，走路 0.57 / 0.64，**两类直接交错**。

**我做的验证**：扫了 10 个候选特征，单特征最优也只有 9/10，而且明显是过拟合。
但有一条规律很清楚：**下台阶靠「正负差 + 偏度」（波形形状）跨人 2/2 全对**。

**结论**：**能跨人的判据靠形状，不能跨人的判据靠习惯。**
`自相关` 测的是「你怎么拿手机」，不是「你在做什么」。
这是整个课题 08 最重要的一句。

## 案 3｜「拒答」是我提的，被否了

**问题**：跨人 3/6 之后，我的方案是加一个「无法判定」分支 ——
自相关落在 0.50–0.70 之间、或能量太低时，不猜，直接说「判不了」。

**结果**：单人 8 段变成「6 对 / 0 错 / 2 拒答」，跨人「3 对 / 0 错 / 3 拒答」，看起来比「3 对 / 3 错」体面。

**用户否决（原话要点）**：「你不能认输……考试的时候问你动作你说不知道那是很有问题的，**宁愿测错也不能说不知道**，这是原则。」

**我的反思**：他说得对，但我当时没意识到问题在哪。后来想清楚了 ——
**「拒答」是把系统的不确定性转嫁给用户**，而用户要的是「给个答案，并告诉我有多可信」。
这两件事在工程上是不同的：前者是逃避，后者是标记。

**改法**：取消全部拒答分支，所有输入必须输出一个类别。
腾出来的精力用来**把判据本身做对**：

- 走路 vs 上楼：`自相关 + 正负差`，训练集零错，最近一对差 0.041；
- 后来加 `+0.2×max(0, 偏度)`，空隙从 0.010 拉到 **0.070**；
- 阈值 0.631。

**结论**：0 拒答 + 更宽的间隔，比「高准确率 + 大量拒答」诚实得多，也实用得多。
这一条改变了后面所有判据的设计思路。

## 案 4｜快下楼：形状判据整个失效

**问题**：加了 6 段「专挑快的」录音（快走 ×2、快下楼 ×2、快上楼、慢跑），测出 **4 对 2 错**，错的全是快下楼。

**我的提问**：「快下楼和慢下楼，波形差在哪？」

**AI 的回答**：别猜，画出来。

**我做的验证**：四段同比例画在一起（`fig16_快下楼波形.png`）：

| | 正负差 | 偏度 |
|---|---|---|
| 慢下楼（尖峰型） | +0.060 | +0.44 |
| 上楼 a（对称） | −0.021 | −0.13 |
| **快下楼1** | **+0.035** | **+0.25** |
| **快下楼2** | **−0.000** | **−0.18** |

**快下楼2 的形状和上楼一模一样。**

**根因**：判下台阶靠的是「触地那一下的冲击」。下得快的时候，腿会主动缓冲，冲击被吃掉了，
波形变对称 —— 形状信息**物理上就不存在了**。

**改法**：形状失效时退回幅度 —— 新增分支 ④b：`RMS ≥ 6.0 且步频 < 1.9 → 下台阶`。
实测：快下楼 6.43 / 6.98，上楼最高 5.58，门槛 6.0 落在中间。

**代价**：4b 的余量只有 **0.42 dB**，是全套规则第二薄的地方。
所以补采清单里一直挂着「用力上楼 3 段」—— 就是去撞这条边界的。

## 案 5｜「留一法 9/10」是我自己算错的

**问题**：加完偏度项后，我报的是「训练集 0 错，留一法 9/10」。

**AI 的回答**：等等，留一法的实现有问题 —— 你的阈值是在**百分位网格**上扫的，跳过了真实空隙。
正确做法是每次留一个样本，用剩下的样本取「两类最近点的中点」当阈值。

**我做的验证**：重写后：

- 留一法 **10/10**；
- **按人留出 ①**：只用本人 6 段定阈值 0.5774 → 判两位同学 4 段 → **4/4**；
- **按人留出 ②**：只用同学 4 段定阈值 0.5659 → 判本人 6 段 → **6/6**。

两个阈值落在同一个空隙里（0.5562–0.5974），中点 0.577。

**结论**：**我原来的 9/10 不是模型的问题，是我评估代码的问题。**
这件事的教训比「10/10」本身重要：
> 报一个数字之前，先确认算这个数字的代码是对的。

后来在课题 06 里也犯过一次同类错误（校准当公共分量），见 `01` 篇案 5。
